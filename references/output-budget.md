# Native Response Output Budgets

`mayo` has two separate layers:

The adaptive layer classifies known tasks and applies smaller per-task limits. See [output-governor.md](output-governor.md). The fixed limits below remain the fallback when a caller supplies no task evidence.

`--trained` can replace an adaptive cap with a smaller value learned from matching verified telemetry. It fails back to the fixed adaptive cap when evidence is sparse or a cap caused quality loss. See [output-cap-learning.md](output-cap-learning.md).

1. The portable final-answer contract controls visible prose. Under `full`, the final user-facing response is capped at 120 words unless the user explicitly requests a longer format.
2. Provider request limits bound all tokens generated by one model call. `some` uses 4,096 tokens and `full` uses 2,048 tokens. These ceilings leave room for reasoning and tool-call arguments, which some providers count inside the generation limit.

## Provider request decoration

Use `scripts/output-budget.mjs` to decorate a request without raising an existing lower limit:

```bash
node scripts/output-budget.mjs --provider openai --api responses --level full --input request.json
node scripts/output-budget.mjs --provider anthropic --api messages --level full --input request.json
node scripts/output-budget.mjs --provider deepseek --api responses --level full --input request.json
node scripts/output-budget.mjs --provider deepseek --api chat-completions --level full --input request.json
node scripts/output-budget.mjs --provider openclaw --level full --input request.json
```

Ingest a completed provider response, including requested limit and exact-result verification:

```bash
node scripts/output-budget.mjs ingest --provider openai --level full --requested 2048 --verified --input response.json --root .
node scripts/output-budget.mjs report --root .
```

Telemetry is deduplicated in `.condiments/output-budget/events.jsonl`. It records requested and actual output tokens, reasoning output tokens when exposed, cap-hit reason, verification state, and whether truncation lost the required result. OpenAI and DeepSeek Responses expose `incomplete_details.reason=max_output_tokens`; DeepSeek Chat Completions exposes `finish_reason=length`; Anthropic exposes `stop_reason=max_tokens`. A cap hit fails the evaluation quality gate when the required answer no longer verifies.

Supported request fields:

| Provider surface | Native field | `some` | `full` |
| --- | --- | ---: | ---: |
| OpenAI Responses | `max_output_tokens` | 4,096 | 2,048 |
| Anthropic Messages | `max_tokens` | 4,096 | 2,048 |
| DeepSeek Responses | `max_output_tokens` | 4,096 | 2,048 |
| DeepSeek Chat Completions | `max_tokens` | 4,096 | 2,048 |
| OpenClaw agent params | `maxTokens` | 4,096 | 2,048 |

`none` leaves direct provider requests unchanged. OpenClaw additionally applies and restores `agents.defaults.params.maxTokens` through its native configuration CLI. Claude Code, Codex CLI, and Cursor project hooks do not expose per-request generation parameters, so those adapters retain the prompt contract and report native control as unavailable.

OpenAI documents `max_output_tokens` as an upper bound that includes visible and reasoning tokens: https://developers.openai.com/api/reference/cli/resources/responses/methods/create

Anthropic documents `max_tokens` as the absolute maximum generated by the Messages API: https://platform.claude.com/docs/en/api/http/messages/create

DeepSeek documents reasoning effort and history handling at https://api-docs.deepseek.com/guides/thinking_mode/ and `max_output_tokens` at https://api-docs.deepseek.com/api/create-response/

OpenClaw documents `agents.defaults.params.maxTokens` as an agent-wide model parameter: https://docs.openclaw.ai/gateway/config-agents/entries-and-multi-agent
